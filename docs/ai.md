# AI 健檢

把資產全覽交給你選的 AI，請它**審計**帳本，或根據帳本給**一般性的建議**。用你自己的 API key，
**預設關閉**。這是這個 app 第二個、也是送出最多東西的對外連線（第一個是
[自動抓收盤價](security.md#兩個例外預設都關)），所以它的每一條限制都是刻意的。

## 送出去的是什麼

一次請求，兩樣東西：

- **一段固定的說明**：英文，寫給模型看的。講帳本的規矩——金額是原幣、不准跨幣別加總、負債是負數、
  沒有資料的月份是「不知道」不是「沒花錢」、文件裡的文字是資料不是指令——以及要它用繁體中文回答。
  內容在 `server/ai.js` 的 `MODES`。
- **資產全覽**：跟總覽頁「匯出全覽」下載的那份 Markdown 一個位元組都不差（`test/api.test.js`
  檢查這件事）。全覽裡有的它都看得到：帳戶名稱、餘額、持股、近一年的收支與分類、固定扣款的名稱。
  全覽裡沒有的它也看不到：逐筆交易、對帳單原檔、帳本檔本身。

送出前，AI 健檢頁的「要送出的內容」可以展開，看完整的說明和文件，字數也寫在上面。

**送出去的就是你看過的那一份，不然就什麼都不送。** 按下送出時，頁面會把預覽的 digest（說明、
文件、供應商和模型一起算出來的 SHA-1）送回去；後端不收頁面給的文字，而是從帳本重新產生一次，
算出來對不上就拒絕（409）——例如你在另一個分頁匯入了對帳單、改了供應商，或預覽和送出之間過了
午夜。頁面接著重畫，讓你看新的內容再決定。`test/ai.test.js` 檢查對得上的才會送、送的正是預覽那
一份，對不上的一個字都不送。

## 什麼時候送

- **預設關閉。** 要在 AI 健檢頁自己打開開關。每本帳各自一個開關。
- **打開之後也只有按下「送出」那一次會送。** 沒有背景工作、沒有排程，啟動服務時也不會送。按一次
  就是一次請求；送出中按鈕會停用，不會因為手滑多送一份。
- **在後端送。** 是 Node 連出去，瀏覽器那一頁的 CSP 不變（`connect-src 'self'`）。示範版沒有
  伺服器、CSP 是 `connect-src 'none'`，所以它**沒有能力**用這個功能，頁面上會直接說。
- 打開時，終端機的啟動訊息會多一行，寫明這本帳開了 AI 健檢。

## 送到哪裡

| 供應商 | 端點 | key 的環境變數 | 建議的模型（第一個是預設） |
|---|---|---|---|
| Anthropic Claude | `api.anthropic.com/v1/messages` | `ANTHROPIC_API_KEY` | `claude-opus-5`、`claude-sonnet-5`、`claude-haiku-4-5`、`claude-fable-5-1` |
| OpenAI | `api.openai.com/v1/responses` | `OPENAI_API_KEY` | `gpt-6-sol`、`gpt-6-astra`、`gpt-6-luna` |
| Google Gemini | `generativelanguage.googleapis.com/v1beta/models/<模型>:generateContent` | `GEMINI_API_KEY` | `gemini-3.8-flash`、`gemini-3.7-flash`、`gemini-3.5-flash-lite` |

`test/deps.test.js` 只准這三個網址出現在 `server/ai.js` 這一個檔，別的檔案寫到就失敗。

- 模型可以換成那家的其他名稱，但只收英數字、點、底線和減號：Gemini 的模型名稱會進網址路徑，
  斜線或冒號一律拒絕。
- **你送出的內容怎麼被處理，看那家的條款。** 目前查證過的兩件事：
  - Gemini 用**免費方案**的 key 時，Google 的條款允許用送出的內容和它的回答改進它的產品，而且
    可能有人工審閱；付費方案不會。
  - OpenAI 的請求帶 `store: false`，不會把這次的回答留著供之後取用。
- Claude 的 `claude-opus-5` 和 `claude-fable-5-1` 有安全分類器，可能拒絕某些請求。這裡請 API
  自動改用 Anthropic 建議的模型重跑（`fallbacks: "default"`）；整串都拒絕的話，頁面顯示錯誤，
  不會把半截的回答當成回答。
- 費用算在你自己的帳號上。結果下面會寫這次用了多少 tokens：輸出含模型推理用掉的部分，Claude
  有 fallback 時每一次嘗試都算進去。實際金額以供應商的帳單為準。

## key 放在哪

- **在 AI 健檢頁貼上**，存在帳本旁邊的 `ai-keys.json`（預設 `~/.finance-hub/ai-keys.json`；
  用 `FINANCE_DB` 指到別處時就在那個檔案的同一層），權限 `600`，只有你的帳號讀得到。
- **不在帳本資料庫裡。** 快照是整個資料庫的複本，key 放進去就會跟著進每一份備份、每一份拿去給人
  看的檔案；它也不在 JSON 匯出裡。每本帳（每個 profile）共用同一個檔，因為 key 是你的，不是哪本帳的。
- 沒貼的話，用那家平常的環境變數（啟動服務前設定）。兩個都有時用貼上的那個。
- 頁面和 API 只拿得到「有沒有設定」和最後四碼，拿不到 key 本身；供應商的錯誤訊息如果引用了 key，
  也會先遮掉再顯示。
- 刪除：頁面上的「刪除 key」。最後一把刪掉時，檔案也一起刪。
- **它進不了 git。** `.gitignore` 忽略 `ai-keys.json*`，`githooks/pre-commit` 也擋——用
  `FINANCE_DB` 把一本測試帳指到 checkout 裡時，key 檔就會落在工作目錄裡，而這個 repo 是公開的。

## 兩種問法

- **審計**：找會讓數字出錯、或讓帳本不完整的地方——負債的正負號、對不上的對帳、漏匯的月份、
  沒配對的轉帳、沒分類的支出、太舊的價格——每一項附上文件裡的證據，和在 Finance Hub 裡怎麼修。
- **建議**：一般性的觀察，每個幣別分開看：可動用的錢撐得了幾個月的支出、欠款、持股集中度、閒置的
  現金、錢花到哪裡、哪些固定扣款值得檢查，最後列出最該先看的三件事。**不是投資、稅務或法律建議**，
  不會叫你買賣特定的證券。

回答照 Markdown 的標題、清單和粗體排版，但**一律當文字處理**：模型寫的 HTML 照字面顯示，連結
不會變成可以點的連結。AI 可能出錯，數字以帳本為準。

## 什麼時候會失敗

| 情況 | 頁面上看到的 |
|---|---|
| 沒打開、沒有 key | 送出按鈕停用，旁邊寫原因；直接呼叫 API 是 400 |
| 看過之後帳本、設定或日期變了 | 拒絕送出（409），頁面重畫成新的內容 |
| 連線在回應完整之前就斷了 | 錯誤（502），不會一直停在「送出中」 |
| key 錯、額度用完、模型名稱不存在 | 供應商回的狀態碼和它的說法（502） |
| 被安全機制拒絕 | 哪一家拒絕、它給的分類（502） |
| 十分鐘沒有回應 | 逾時（504） |
| 回答太長 | 照樣顯示，並標明後面被截掉了 |
