# 你的資料放在哪

**帳本不在 repo 裡面。** repo 會被 clone、`git clean`、開 branch、開 worktree、砍掉重來；
帳本要留十年。兩者生命週期不同，所以不住在一起。

```
~/.finance-hub/finance.db     ← 你的帳本
~/.finance-hub/backups/       ← 匯入前、升級結構前的自動快照
```

放在 `<repo>/data/` 會是什麼結果：`.gitignore` 擋得住 commit，但**`git clean -xdf` 會把整
個 `data/` 刪掉**——連快照一起，而那是「整理工作區」的標準指令，不是危險指令。而且每開一個
worktree 就多一個空的 `data/`，在裡面跑會看到一本空帳。

## 同時要一本測試用的帳

```bash
node server/index.js                        # 個人帳本
FINANCE_PROFILE=demo node server/index.js   # ~/.finance-hub/demo.db
FINANCE_DB=/tmp/whatever.db node server/index.js
```

`FINANCE_DB` 優先於 `FINANCE_PROFILE`，兩者都不給就是個人帳本。profile 名稱會變成檔名，所以
限制在 `^[A-Za-z0-9_-]{1,32}$`。

不是個人帳本時，終端機會標出來，側邊欄那顆徽章也會從綠色變琥珀色並寫出 profile 名稱。兩個
視窗長得一模一樣、網址也一樣，沒有標示遲早會在 demo 裡輸入真資料。

### 讓 demo 帳本裡有東西

```bash
FINANCE_PROFILE=demo node scripts/seed-demo.js
FINANCE_PROFILE=demo node server/index.js
```

塞進三年、十個帳戶、兩種幣別的編造資料：現金、信用卡、貸款、券商交割戶、一個冷錢包、
一個有未歸屬提撥的 401(k)，加上台股、美股持股和一枚八位小數的幣。**每個數字都是編的**，跟
`test/fixtures/` 同一條規則。

它的形狀是刻意調過的，不是隨便生一堆列 —— 一本只有現金帳戶的帳本，每張佔比圖都是
「現金／存款 100%」，圖表為了資產與負債設計的那個發散色階永遠不會出現。所以它一定會產生：

- 每個幣別至少兩種帳戶類型，而且一定有負債（負數）
- 完整度的**五種狀態全部出現** —— 有資料、確認過、只涵蓋一半、缺口、還沒開始
- 抓得到的固定扣款，而且不會是轉帳（大部分的轉帳已經先配對好）
- 一部分有分類、一部分沒有，這樣才看得出分類規則在做什麼
- 幾筆待配對轉帳和一筆對不上的對帳，讓總覽的待辦清單不是空的

**它拒絕寫入個人帳本**，不是警告是拒絕：這個腳本會塞進幾百筆假交易，而能覆蓋真實帳本的
seeder 離最糟的 bug 只差一個手誤。`--force` 只會清掉目標那一本。亂數吃固定種子，所以同一
個指令跑兩次結果一樣，測試才有基準可以比。

## 備份

`~/.finance-hub/finance.db` 就是全部。複製它就是完整備份。

**每本帳的備份各自一個資料夾，名字就是帳本的名字：**

```
~/.finance-hub/backups/personal/    個人帳本
~/.finance-hub/backups/demo/        FINANCE_PROFILE=demo
```

它們共用 `~/.finance-hub`，所以以前也共用同一個 `backups/` —— 那有兩個問題，而且都是安靜
的：修剪只保留「那個資料夾裡」最新的 N 份，所以在 demo 帳本裡匯入個幾次就會把個人帳本的快
照刪光；而快照的檔名只寫時間、不寫是哪一本帳，兩邊放在一起長得一模一樣，還原時拿錯就是把
編出來的資料蓋到真帳戶上。

個人帳本也放進 `personal/` 而不是留在外層：一條規則沒有例外，打開資料夾就知道裡面是什麼，
不用先去讀程式碼。舊版本寫在外層的快照**不會自動搬**，要的話自己 `mv` 進去 —— 1.0 之前東
西還在動，為了省一次 `mv` 而永遠背著一段一次性的搬檔程式碼不划算。

檔名刻意維持原狀沒有加 profile 前綴：修剪是靠檔名排序來排時間的，加了前綴會讓 `d` 排在
`p` 前面這件事蓋過時間戳，刪錯檔案。資料夾裡只有一本帳，檔名沒有東西要區分。

**自動快照有兩個時機**，都存到帳本旁邊的 `backups/`（預設 `~/.finance-hub/backups/`；用
`FINANCE_DB` 指到別的地方時，就在那個檔案的同一層），檔名帶時間戳和用途：

- **每次 CSV 匯入前**（`-preimport`）。匯入是唯一一次寫入上百筆的動作，而欄位對應選錯
  往往是事後才發現——有快照的話，回復就只是複製一個檔。備份失敗會**中止匯入**而不是
  照樣寫下去。
- **升級資料庫結構前**（`-migrate`），而且只在帳本裡已經有東西的時候。全新的檔案不會拍，
  空資料庫沒什麼好備份的。結構怎麼改見 [`money.md`](money.md)。

保留最近 10 份（`KEEP_BACKUPS` 可調，但最少留 1 份——剛拍好那份不會被自己的清理刪掉，
不然系統會回報一個已經不存在的備份）。

複製用的是 SQLite 自己的 `VACUUM INTO`，不是 `cp`：WAL 模式下光複製 `.db` 會漏掉還沒寫回
主檔的交易。先寫成 `.part` 再改名，所以半途中斷不會留下一個「看起來像備份」的壞檔。出來的
是一個乾淨的單檔（沒有 `-wal`、`-shm`），要還原就是把它蓋回 `finance.db`，順手把舊的
`-wal` / `-shm` 刪掉。

（如果複製到一半被中斷，`backups/` 裡會留下一個 `.part` 檔。它不會被列出來、也不會被當成
可還原的備份，純粹佔空間，可以直接刪。）

設定頁也可以匯出完整 JSON，或匯出給 Excel 看的 CSV（UTF-8 BOM，中文不會亂碼）。

## 不讓資料跑進版控

兩層，因為任何一層都可能失手：

1. **`.gitignore`** —— 擋 `*.db`、`data/`、`.env`，以及**所有 `*.csv` 和 `*.pdf`**。對帳單
   存進來時叫 `stmt.csv`、`eStmt_2025-04-01.csv` 或 `Statement.pdf`，比對不到任何特定檔名，
   所以整類擋掉。
2. **`githooks/pre-commit`** —— `.gitignore` 擋不住 `git add -f`，也管不到已經被追蹤的檔案。
   這個 hook 看的是「實際被 stage 的東西」，抓到就擋下 commit。每個 clone 要開一次：

```bash
git config core.hooksPath githooks
```

唯一的例外是 **`test/fixtures/` 裡的 `.csv` 和 `.pdf`**：測試用的樣本檔，內容全部是編的，只
有格式是從真實對帳單抄下來的。兩層都是**按路徑**放行、不看內容，所以下載回來的對帳單不要往
那個資料夾放。機械性的那半是 `api.test.js` 會檢查那裡的每個檔案都有測試在讀——丟進去又忘記
的檔案會讓測試紅掉。細節在 `test/fixtures/README.md`。

真的要放行：`git commit --no-verify`。
